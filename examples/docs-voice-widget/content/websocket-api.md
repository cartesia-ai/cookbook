# WebSocket API

> Stream audio and events between your application and an agent.

Connect your application to an existing Managed Agent over one bidirectional WebSocket to send user audio, receive agent audio, and handle conversation or client-tool events.

This page assumes you already created and configured an agent. Reuse its `agent_id` for each new conversation. See [Managed Agents](/agents/introduction) to create an agent and [Agent configuration](/agents/configuration) to configure it.

## Prerequisites

* An existing Managed Agent and its `agent_id`
* A Cartesia API key for a trusted server, or an [agent access token](/api-reference/auth/access-token#body-grants-agent) generated by your server for a browser or mobile app
* Code that reads audio from an input source, such as a microphone or file, and produces bytes in a supported [audio format](#audio-formats)
* Code that plays or otherwise handles the agent audio returned in that same format

### Audio formats

`input_format` is required. It selects headerless, mono audio:

| `input_format` | Wire representation |
| - | - |
| `pcm_16000`, `pcm_24000`, `pcm_44100` | 16-bit PCM; two bytes per sample |
| `mulaw_8000` | 8-bit μ-law; one byte per sample |

Agent audio uses the same format as input.

## Quick start

This Node.js session skeleton uses an API key from a trusted server. It connects, sends `session_create`, waits for `session_ready`, and converts returned base64 audio to bytes. Connect the three audio integration points after the example.

Install the [`ws`](https://www.npmjs.com/package/ws) package:

```bash
npm install ws
```

Save this as `agent-session.mjs`:

```javascript agent-session.mjs
import WebSocket from "ws";

const agentId = process.env.CARTESIA_AGENT_ID;
const apiKey = process.env.CARTESIA_API_KEY;

if (!agentId || !apiKey) {
  throw new Error("Set CARTESIA_AGENT_ID and CARTESIA_API_KEY");
}

const ws = new WebSocket(
  `wss://api.cartesia.ai/v1/agents/websocket/${agentId}` +
    "?cartesia_version=2026-08-14",
  { headers: { "X-API-Key": apiKey } }
);

let ready = false;
let callId;

ws.on("open", () => {
  ws.send(JSON.stringify({
    type: "session_create",
    audio: {
      input_format: "pcm_44100",
      output_delivery: "speaking_pace",
    },
  }));
});

ws.on("message", (data) => {
  const event = JSON.parse(data.toString());

  if (event.type === "session_ready") {
    ready = true;
    callId = event.call_id;
    console.log("Session ready:", callId);
  }
  if (event.type === "audio_output") playAudio(decodeAudio(event.audio));
  if (event.type === "audio_output_clear") stopPlayback();
});

function sendAudio(audioBytes) {
  if (!ready) return;
  const base64Audio = Buffer.from(audioBytes).toString("base64");
  ws.send(JSON.stringify({ type: "audio_input", audio: base64Audio }));
}

function decodeAudio(base64Audio) {
  return Buffer.from(base64Audio, "base64");
}

function playAudio(audioBytes) {
  console.log("Received agent audio bytes:", audioBytes.byteLength);
}

function stopPlayback() {
  console.log("Received audio_output_clear");
}

ws.on("close", (code, reason) => console.log("Closed:", code, String(reason)));
ws.on("error", console.error);
```

From a browser or mobile app, never embed an API key. Mint a short-lived [agent access token](/api-reference/auth/access-token#body-grants-agent) on your server and pass it as a query parameter, browsers cannot set WebSocket headers.

```javascript
const ws = new WebSocket(
  `wss://api.cartesia.ai/v1/agents/websocket/${agentId}` +
    `?cartesia_version=2026-08-14&access_token=${accessToken}`
);
```

Run the skeleton:

```bash
CARTESIA_AGENT_ID="agent_..." CARTESIA_API_KEY="sk_..." node agent-session.mjs
```

To complete the audio path:

* Call `sendAudio(audioBytes)` for each audio input chunk. `audioBytes` must contain bytes in the `input_format` selected in `session_create`; the function base64-encodes and sends them, then returns nothing.
* Replace `playAudio(audioBytes)` with a function that queues its bytes for playback in that same format, then returns nothing.
* Replace `stopPlayback()` with a function that takes no arguments, discards queued output, stops current playback, and returns nothing.

## Connect

```text
wss://api.cartesia.ai/v1/agents/websocket/{agent_id}?cartesia_version=2026-08-14
```

Server applications authenticate with the `X-API-Key` header. Browser and mobile applications should send an `access_token` query parameter. Never expose an API key in a client application. See [Authenticate your applications](/get-started/authenticate-your-client-applications) for token handling.

The connection captures the agent's current version when it opens. A configuration change does not affect a call already in progress. The `session_ready` event reports the resolved `agent_version_id` and the call's `call_id`.

## Start the session

Send `session_create` as the first event, within 10 seconds of connecting:

```json
{
  "type": "session_create",
  "audio": {
    "input_format": "pcm_44100",
    "output_delivery": "speaking_pace"
  }
}
```

`output_delivery` defaults to `speaking_pace`. Use `as_available` when your application manages its own playback buffer. `as_available` cannot be used when the agent has background audio configured.

Wait for `session_ready` before sending audio:

```json
{
  "type": "session_ready",
  "call_id": "ac_gqkgRWUz2u64qFUjA1mZyr",
  "agent_id": "agent_Fo7pKNBUwLZxrTd6jvhpaE",
  "agent_version_id": "av_7Hq2mXbK9cLdNfPzR3tWvE",
  "audio": {
    "input_format": "pcm_44100",
    "output_delivery": "speaking_pace"
  }
}
```

See the [Agent WebSocket API reference](/api-reference/agents/agent-websocket) for every `session_ready` field.

## Stream audio

All events use JSON text frames. For both `audio_input` and `audio_output`, base64-encode the binary audio bytes in the event's `audio` string; do not send binary WebSocket frames.

Send user audio as `audio_input` events.

```json
{
  "type": "audio_input",
  "audio": "base64_encoded_audio_data"
}
```

The server returns `audio_output` events in the configured format:

```json
{
  "type": "audio_output",
  "audio": "base64_encoded_audio_data"
}
```

When the user starts speaking, the server sends `audio_output_clear` (barge-in). Discard buffered agent audio and stop playback immediately. The event can arrive while no agent audio is playing, in which case there is nothing to clear.

## Client tools

When the agent invokes a [client tool](/agents/client-tools), the server sends `client_tool_call`:

```json
{
  "type": "client_tool_call",
  "tool_call_id": "call_2b7e4f9a1c0d",
  "tool_name": "lookup_cart",
  "parameters": { "cart_id": "cart_456" },
  "expects_response": true
}
```

If `expects_response` is `true`, answer with the same `tool_call_id`:

```json
{
  "type": "client_tool_result",
  "tool_call_id": "call_2b7e4f9a1c0d",
  "result": "2 items in cart",
  "is_error": false
}
```

Late, duplicate, and mismatched results are ignored. Results may be up to 4096 bytes.

## Conversation events

Use [`turn_started`, `turn_output_text_delta`, and `turn_ended`](/api-reference/agents/agent-websocket) for speaking-state UI, transcripts, and other non-audio workflows. Assistant text arrives incrementally in `turn_output_text_delta`; `turn_ended.text` contains the final text for either role.

Play agent audio from `audio_output`. When `audio_output_clear` arrives, discard queued agent audio and stop playback.

## End the session

Close the WebSocket with code `1000` for a normal client shutdown:

```javascript
ws.close(1000, "session completed");
```

The `call_id` returned in `session_ready` identifies the call record for this session. After the call ends, pass it to the [Get Call endpoint](/api-reference/agents/calls/get-call) to fetch the call record and transcript, or to [Download Call Audio](/api-reference/agents/calls/download-call-audio) to download the call audio. Use [List Calls](/api-reference/agents/calls/list-calls) to find other call records.

## Errors and connection limits

The server sends an `error` event when it rejects an event. A recoverable error has `fatal: false`; a fatal error is followed by a connection close.

* A JSON message may be up to 32 KiB. Larger messages close with code `1009`.
* The server closes after 120 seconds without a valid client event. Streaming audio continuously, including silence, keeps the connection active. WebSocket ping frames do not reset this application-level timer.
* The server uses close code `1008` for protocol errors and `1011` for internal failures.
