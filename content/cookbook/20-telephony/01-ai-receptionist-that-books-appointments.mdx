# Build an AI receptionist that answers the phone and books appointments

A caller asks for a haircut tomorrow afternoon. The agent checks the calendar, reads a time back, and books it. The voice side is a Cartesia Managed Agent, which runs Ink 2 speech to text, an LLM and Sonic 3.6 text to speech as one managed stack. Your code is a FastAPI server that owns the calendar and answers the agent's tool calls.

This recipe covers the Cartesia parts: defining tools, choosing between client and webhook tools, creating the agent, checking webhook calls, and putting the agent on a number. The full app, with setup steps, a call log, Cal.com booking and a browser test page, is the [`examples/front-desk`](../../../examples/front-desk/README.md) template.

## Prerequisites

- A Cartesia API key
- Python 3.12 or newer and [uv](https://docs.astral.sh/uv/)
- For phone calls, a public HTTPS address for the server (a deploy, or a tunnel such as `ngrok http 8000`)

The Python SDK (4.2) has `client.agents` with retrieve, update, list and delete, plus calls, but it can't create agents, tools or webhooks. The template calls the documented paths with httpx instead and sends the `Cartesia-Version` header on every request.

## Define the booking tools

Write each tool once, as a name, a description the LLM reads, and JSON Schema properties. The descriptions carry the rules. `book_appointment` says to call it only after the caller confirmed the time.

```python filename="front_desk/tools.py"
{
    "name": "book_appointment",
    "description": (
        "Books one appointment. Use it only after you have read the date and time back to the caller "
        "and they said yes, and you have their name. The result says if it worked."
    ),
    "properties": {
        "date": {"type": "string", "description": "Appointment day as YYYY-MM-DD."},
        "time": {"type": "string", "description": "Start time from check_availability, like 2:30 PM."},
        "name": {"type": "string", "description": "Caller's full name."},
        "phone": {
            "type": "string",
            "description": "Callback number the caller gave. Empty if they did not give one.",
        },
        "service": {"type": "string", "description": "What the appointment is for, in a few words."},
    },
    "required": ["date", "time", "name"],
},
```

`check_availability` follows the same shape. The handlers return short JSON strings, well under the 4096 byte limit Cartesia sets for a tool result, with days and times in spoken form like "Friday, October 17" and "2:30 PM". A calendar failure comes back as an instruction ("Offer to take a message instead") rather than an exception, so the agent has something to say.

## Client tool or webhook tool

Cartesia can reach a tool two ways. A [client tool](https://docs.cartesia.ai/agents/client-tools) arrives as a `client_tool_call` event on the WebSocket a browser holds open. A [webhook tool](https://docs.cartesia.ai/agents/webhook-tools) is an HTTPS POST from Cartesia to a URL you give it. A phone call has no browser in the middle, so phone calls need webhook tools, and those need a public HTTPS address.

The template picks the mode from one setting. With no `PUBLIC_BASE_URL` it makes client tools, so you can test from a browser on a laptop. With it set, it makes webhook tools. `tool_body` turns a spec into the request for `POST /v1/agents/tools`.

```python filename="front_desk/tools.py"
WEBHOOK_CONTEXT = {
    "call_id": "system__conversation_id",
    "caller_number": "system__caller_id",
    "call_direction": "system__call_direction",
}
```

```python filename="scripts/setup_agent.py"
def tool_body(spec: dict[str, Any], s: Settings, tool_secret: str) -> dict[str, Any]:
    common = {
        "name": spec["name"],
        "description": spec["description"],
        "pre_tool_speech": "auto",
        "execution_mode": "immediate",
        "response_timeout_secs": 15,
    }
    if s.tool_mode == "client":
        return {
            "type": "client",
            **common,
            "expects_response": True,
            "parameters": {"type": "object", "properties": spec["properties"], "required": spec["required"]},
        }
    props = dict(spec["properties"])
    for field, variable in WEBHOOK_CONTEXT.items():
        props[field] = {"type": "string", "dynamic_variable": variable}
    return {
        "type": "webhook",
        **common,
        "api_schema": {
            "url": f"{s.public_base_url}/tools/{spec['name']}",
            "method": "POST",
            "request_body_schema": {"type": "object", "properties": props, "required": spec["required"]},
            "request_headers": {"X-Tool-Secret": {"type": "secret", "secret_value": tool_secret}},
        },
        "assignments": [],
    }
```

The webhook version adds two things. A secret `X-Tool-Secret` header lets your server reject posts that did not come from Cartesia. Three extra properties are bound to system dynamic variables, so Cartesia fills in the call id, caller number and call direction itself. The model never writes those values. It does see the caller number, because the prompt includes `{{system__caller_id}}` so the agent can read it back. `book_appointment` uses the injected `caller_number` when the caller did not say a number.

## Create the agent

The agent body attaches the tools by id and sets the rest of the call. The business name goes into `keyterms` so speech to text spells it right. `transfer_to_number` is only set when you configure a transfer number.

```python filename="scripts/setup_agent.py"
    return {
        "name": f"{AGENT_NAME_PREFIX}: {s.business_name}"[:64],
        "description": "Receptionist from examples/front-desk in the Cartesia cookbook.",
        "config": {
            "instructions": instructions(s),
            "initial_message": greeting(s),
            "timezone": s.timezone,
            "model": {"id": s.model_id, "temperature": 0.4},
            "language": {"primary": "en"},
            "audio": {
                "input": {"noise_suppression": "auto", "keyterms": [s.business_name]},
                "output": {"voice_id": s.voice_id},
            },
            "turn": {"inactivity_check_in_secs": 10, "inactivity_end_call_secs": 120},
            "tools": [{"id": i} for i in tool_ids],
            "system_tools": {
                "end_call": {"description": None, "pre_tool_speech": "force"},
                "transfer_to_number": transfer,
            },
        },
    }
```

The instructions use `{{system__time}}` to resolve "tomorrow" and `{{system__caller_id}}` to know the caller's number. Cartesia fills both per call. The booking steps are spelled out in order.

```md filename="front_desk/prompt.py"
# Booking an appointment
1. Ask what they want booked and which day suits them.
2. Call check_availability with that day as YYYY-MM-DD. Offer two or three of the open times, not all of them.
3. When they pick a time, ask for their name, and a callback number if you do not have one.
4. Read the day, time and name back once and ask "Shall I book that?"
5. Only after they say yes, call book_appointment. If it says booked is false, offer the open times it returns.
Never say an appointment is booked unless book_appointment returned "booked": true.
```

## Answer webhook tool calls

Webhook tool calls come straight from Cartesia, so the route checks the shared secret in constant time before it runs anything. `_json_object` answers 400 unless the body is a JSON object. `Tools.run` is synchronous, so the route runs it in a thread pool instead of blocking the event loop. The browser test page forwards client tool calls to a second route that ends in the same `Tools.run`.

```python filename="front_desk/main.py"
@app.post("/tools/{name}")
async def webhook_tool(name: str, request: Request) -> PlainTextResponse:
    s = settings()
    if name not in TOOL_NAMES:
        raise HTTPException(404, "Unknown tool.")
    given = request.headers.get("x-tool-secret", "")
    if not s.tool_secret or not hmac.compare_digest(given.encode(), s.tool_secret.encode()):
        raise HTTPException(401, "unauthorized")
    params = await _json_object(request)
    return PlainTextResponse(await run_in_threadpool(tools(s).run, name, params))
```

## Check call webhooks

Call events (`call_started`, `call_turn`, `call_completed`, `post_call_analysis`) go to a separate webhook. Cartesia does not sign webhook bodies. It echoes the secret you registered in `x-webhook-secret`, so the handler compares that in constant time, rejects events for other agents, and drops retries by `webhook_request_id`.

```python filename="front_desk/webhooks.py"
    given = headers.get("x-webhook-secret", "")
    if not hmac.compare_digest(given.encode(), secret.encode()):
        return Verdict(401, "unauthorized")
    if not isinstance(body, dict) or not isinstance(body.get("type"), str):
        return Verdict(400, "Not a webhook event.")
    if agent_id and body.get("agent_id") != agent_id:
        return Verdict(400, "Event is for another agent.")
```

## Put the agent on a phone number

1. Deploy the server to any host with HTTPS, or run a tunnel. Cartesia blocks private and non-HTTPS addresses.
2. Set `PUBLIC_BASE_URL` and run the setup script again. It swaps the client tools for webhook tools, generates the tool secret, and registers the call webhook.
3. Attach a number to the agent. Every plan includes at least one free US number from [Cartesia numbers](https://docs.cartesia.ai/line/integrations/telephony/cartesia-numbers). Outside the US, [import a Twilio number](https://docs.cartesia.ai/line/integrations/telephony/twilio/integration) or use [SIP trunking](https://docs.cartesia.ai/line/integrations/telephony/sip-trunking). Then assign it as described in [Phone numbers](https://docs.cartesia.ai/line/integrations/telephony/phone-numbers).
4. For live handoff, set a transfer number and run setup again. Transfers only work on Twilio or SIP calls.

## Before you deploy

Set `DASHBOARD_PASSWORD`. It puts the dashboard, recordings, the token route and the browser's tool route behind HTTP Basic auth, and the app refuses to start without it when `PUBLIC_BASE_URL` is set or uvicorn binds a non-loopback address. `/tools/*` and the call webhook skip that login because Cartesia calls them, and they check their own secrets instead. Behind a proxy such as Render, Fly or Railway, set `TRUST_PROXY=1` so the token rate limit sees the caller's address rather than the proxy's. The browser only ever gets a short-lived access token, as [Browser auth with access tokens](../00-guides/01-browser-auth-with-access-tokens.mdx) explains.

Recording callers has legal requirements that depend on where you and they are. Cartesia records agent calls by default. See [call recordings](https://docs.cartesia.ai/line/infrastructure/observability#call-recordings).

## Limits

The template's tests and the setup script's dry run cover both tool modes. A real phone call through a purchased number was not part of that testing, so place a test call before you rely on it.
