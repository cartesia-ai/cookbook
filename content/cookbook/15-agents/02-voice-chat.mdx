# Build a browser voice chat with a Managed Agent

You press a button, talk to an agent, and can cut in while it is speaking. The browser sends microphone audio straight to Cartesia and plays the agent's audio. Your server creates the agent once and mints a short-lived token for each call, so the API key never reaches the page.

This recipe explains the four pieces that make that work: the agent config, the token route, the browser connection, and barge-in. It ends with a sketch of the same loop using your own LLM. To run the finished app, follow the [`examples/voice-chat`](../../../examples/voice-chat/README.md) README.

## Prerequisites

- A Cartesia API key
- Node 22.22 or newer
- The agent connection basics from [Connect to a Managed Agent from the browser](./01-talk-to-a-managed-agent.mdx)

Agent LLM usage is billed to your Cartesia account.

## Create the agent

A Managed Agent is created once, with a system prompt, a voice and an LLM. The template's setup script sends this body to `POST /v1/agents` and saves the returned id.

```ts filename="scripts/setup-agent.ts"
export function buildBody(env: Env) {
  const config = {
    instructions: INSTRUCTIONS,
    initial_message: INITIAL_MESSAGE,
    model: { id: env.AGENT_MODEL_ID || DEFAULT_MODEL_ID },
    language: { primary: "en" },
    audio: { output: { voice_id: env.CARTESIA_VOICE_ID || DEFAULT_VOICE_ID } },
    speculative_generation: true,
    turn: { inactivity_check_in_secs: 10, inactivity_end_call_secs: 120 },
  };
  return {
    name: "Cookbook voice chat",
    description: "Created by examples/voice-chat in the Cartesia cookbook",
    config,
  };
}
```

`@cartesia/cartesia-js` 4.2.0 has no typed method for the Managed Agents create call, so the script uses the client's generic `client.post(AGENTS_PATH, { body })`, which keeps the auth, retry and `Cartesia-Version` headers.

Model ids change. Check `GET /v1/agents/models` and set `AGENT_MODEL_ID` from that list rather than trusting the default. The agent speaks with Sonic 3.6 because that is the platform default; the config takes a voice id but no text to speech model.

Write the prompt for the ear: one or two short sentences, no lists or markdown, numbers spelled out, one question at a time.

## Mint a token

The browser needs a token to open the WebSocket. This route creates one that lasts 60 seconds and carries only the `agent` grant, so it cannot be used for speech synthesis or transcription.

```ts filename="lib/token-handler.ts"
import { createAgentTokenHandler } from "@/lib/agents-web/server";
import { getApiKey } from "./env";
import { clientIp, createRateLimiter, tooManyRequests } from "./rate-limit";

const headers = { "Cache-Control": "no-store" };

export function createTokenRoute(allow = createRateLimiter(10, 60_000)) {
  return async function POST(req: Request): Promise<Response> {
    const apiKey = getApiKey();
    if (!apiKey) {
      return Response.json(
        { error: "CARTESIA_API_KEY is not set. Add it to .env.local and restart." },
        { status: 503, headers },
      );
    }
    if (!allow(clientIp(req))) return tooManyRequests(headers);
    const res = await createAgentTokenHandler({ apiKey, expiresIn: 60 })(req);
    if (!res.ok) {
      return Response.json({ error: "Could not get a Cartesia token. Check the API key." }, { status: 502, headers });
    }
    return res;
  };
}
```

`app/api/token/route.ts` is one line, `export const POST = createTokenRoute();`. The route checks the rate limit (10 tokens a minute per client IP) before it asks Cartesia for a token, answers 429 when the limit is hit, and answers 502 with a fixed message when Cartesia refuses. The upstream error body never reaches the page.

`clientIp` in `lib/rate-limit.ts` decides which IP the limit counts against:

```ts filename="lib/rate-limit.ts"
export function clientIp(request: Request): string {
  const forwarded = (request.headers.get("x-forwarded-for") ?? "")
    .split(",")
    .map((part) => part.trim())
    .filter(Boolean);
  if (process.env.VERCEL) return forwarded[0] ?? "global";
  if (process.env.TRUST_PROXY === "1") return forwarded[forwarded.length - 1] ?? "global";
  return "global";
}
```

A caller can write anything into `x-forwarded-for`, so the function only reads it where a proxy you trust sets it: on Vercel, or behind your own proxy with `TRUST_PROXY=1`. Anywhere else every caller shares one bucket. The limit lives in memory on one server instance, so treat it as a demo guard. The template's `proxy.ts` asks for `APP_PASSWORD` on every page and route when it is set, and that password is the real guard. For per-user access, add your own session check before the token call, as in [Browser auth with access tokens](../00-guides/01-browser-auth-with-access-tokens.mdx). Anyone who can call this route can start calls on your account.

The agent id is not secret. The page reads `CARTESIA_AGENT_ID` on the server and passes it down as a prop.

## Connect from the browser

`useCartesiaAgent` (from [`packages/agents-web`](../../../packages/agents-web/README.md), which the template copies into `lib/agents-web`) asks for the microphone, opens the socket, sends `session_create` first, streams 16 kHz microphone audio, plays the agent's audio, and drops queued audio the moment the agent is interrupted.

```tsx filename="components/voice-chat.tsx"
import { useCartesiaAgent } from "@/lib/agents-web/react";

async function getToken(): Promise<string> {
  const res = await fetch("/api/token", { method: "POST" });
  const body = (await res.json().catch(() => ({}))) as { token?: string; error?: string };
  if (!res.ok || !body.token) throw new Error(body.error ?? `Token request failed (${res.status})`);
  return body.token;
}

export function VoiceChat({ agentId }: { agentId: string }) {
  const agent = useCartesiaAgent({
    agentId,
    getToken,
  });
```

The template's view takes plain props (`agent.status`, `agent.messages`, `agent.isSpeaking`, `agent.muted`, `agent.error`), so its tests render every state without a socket. Call `start()` from a click, because browsers only allow the microphone and audio playback after a user gesture. `getToken` runs once per `start()`, so a retry always gets a fresh token. The client sets `output_delivery: "as_available"` in `session_create`, so Cartesia sends audio as soon as it is ready and the client owns the playback queue and can empty it on interruption.

These are the server events the client handles for you.

| Event | What the client does |
| --- | --- |
| `session_ready` | Marks the call ready and starts sending microphone audio |
| `audio_output` | Decodes the audio and queues it for playback |
| `audio_output_clear` | Empties the playback queue at once |
| `turn_started`, `turn_output_text_delta`, `turn_ended` | Builds the transcript |
| `client_tool_call` | Runs the handler you pass in `tools` and sends the result back |
| `error` | Surfaces it, and a fatal one ends the call |

## Captions and barge-in

Assistant text streams in as the agent speaks. Append each `turn_output_text_delta` as is, because the deltas already contain their spaces. When the turn ends, the server's final `text` replaces the streamed text.

Your own words arrive only when your turn ends, in `turn_ended`. The template shows animated dots while you speak. If you need partial user captions, use your own LLM as below, where Ink 2 sends them.

Barge-in happens in two places. The service stops generating when it hears you and sends `audio_output_clear`, and the client empties its playback queue. The assistant turn then ends with `interrupted: true`, and its `text` holds only what the agent actually said, so replacing the streamed text cuts the bubble to the spoken words.

Use headphones. The client asks the browser for echo cancellation, which helps, but on speakers the agent can still hear and interrupt itself.

## Use your own LLM

The managed agent picks the LLM from Cartesia's list. For any other model, or full control of the loop, run the pieces yourself: Ink 2 for speech to text, your model behind a streaming route, and Sonic 3.6 for speech. The browser talks to Cartesia with a token minted the same way as above, but with `grants: { stt: true, tts: true }` instead of `agent`.

The code below is a sketch for this path. It is not part of the voice-chat template, which uses the managed agent. The [pocket interpreter](../../../examples/pocket-interpreter) template runs the same Ink 2, LLM and Sonic loop in full.

Listening sends microphone chunks to `client.stt.autoFinalize.websocket` and turns its events into turns. `startMic` runs an `AudioWorklet` and sends Float32 chunks of about 100 ms at the context's sample rate. `turn.update` gives partial text for the user. On `turn.end`, use `transcript` exactly as it is.

```ts
import type Cartesia from "@cartesia/cartesia-js";

const CHUNK_MS = 100;

async function startMic(audioCtx: AudioContext, onChunk: (chunk: ArrayBuffer) => void) {
  const worklet = `
    class PCMCapture extends AudioWorkletProcessor {
      process(inputs) {
        const ch = inputs[0]?.[0];
        if (ch) this.port.postMessage(ch);
        return true;
      }
    }
    registerProcessor("pcm-capture", PCMCapture);`;
  const url = URL.createObjectURL(new Blob([worklet], { type: "application/javascript" }));
  await audioCtx.audioWorklet.addModule(url);
  URL.revokeObjectURL(url);

  const stream = await navigator.mediaDevices.getUserMedia({ audio: { echoCancellation: true } });
  const source = audioCtx.createMediaStreamSource(stream);
  const node = new AudioWorkletNode(audioCtx, "pcm-capture");
  const size = Math.round((audioCtx.sampleRate * CHUNK_MS) / 1000);
  let pending = new Float32Array(0);
  node.port.onmessage = (e: MessageEvent<Float32Array>) => {
    const joined = new Float32Array(pending.length + e.data.length);
    joined.set(pending);
    joined.set(e.data, pending.length);
    let at = 0;
    for (; joined.length - at >= size; at += size) onChunk(joined.slice(at, at + size).buffer);
    pending = joined.slice(at);
  };
  source.connect(node);

  return {
    stop() {
      source.disconnect();
      node.disconnect();
      stream.getTracks().forEach((t) => t.stop());
    },
  };
}

export interface ListenHandlers {
  onTurnStart(): void;
  onPartial(transcript: string): void;
  onTurnEnd(transcript: string): void;
}

export async function listen(client: Cartesia, audioCtx: AudioContext, handlers: ListenHandlers) {
  const ws = client.stt.autoFinalize.websocket({
    model: "ink-2",
    encoding: "pcm_f32le",
    sample_rate: audioCtx.sampleRate,
  });
  ws.on("error", (err) => console.error(err.message));

  const mic = await startMic(audioCtx, (chunk) => ws.sendRaw(chunk));

  const done = (async () => {
    for await (const event of ws.stream()) {
      if (event.type !== "message") continue;
      const m = event.message;
      if (m.type === "turn.start") handlers.onTurnStart();
      else if (m.type === "turn.update") handlers.onPartial(m.transcript);
      else if (m.type === "turn.end") handlers.onTurnEnd(m.transcript);
    }
  })();

  return {
    done,
    stop() {
      mic.stop();
      ws.send({ type: "close" });
    },
  };
}
```

Speaking opens one text to speech context per reply on a shared `client.tts.websocket()`. Split the LLM stream into sentences and push each one as it completes, so the first sentence plays while the model is still writing. With `max_buffer_delay_ms: 0`, Sonic starts on each push instead of waiting for more text. With `add_timestamps`, you know which words have played.

```ts
const current = ws.context({
  model_id: "sonic-3.6",
  voice,
  output_format: { container: "raw", encoding: "pcm_f32le", sample_rate: 44100 },
  language: "en",
  add_timestamps: true,
  max_buffer_delay_ms: 0,
});
for await (const event of current.receive()) {
  if (event.type === "chunk" && event.audio) scheduleOnWebAudioClock(event.audio);
  else if (event.type === "timestamps" && event.word_timestamps) recordWords(event.word_timestamps);
}
```

In that loop, push sentences with `current.push({ transcript })` and finish with `current.no_more_inputs()`. `scheduleOnWebAudioClock` and `recordWords` stand for your own playback and bookkeeping.

Barge-in is your job now. When Ink 2 reports `turn.start` while the agent is talking, abort the LLM request, call `current.cancel()`, stop every scheduled `AudioBufferSourceNode`, and cut the assistant message to the words whose timestamp is before the current playback time. That last step keeps the conversation history honest, so the LLM does not think it said things the user never heard.

The trade is plain. The managed agent is one token route, and the service owns turn taking. Your own LLM gives you any model and every step of the loop, and you own the turn logic, barge-in, and the cost of each service.

## Troubleshooting

- **The call closes right away with 1008.** The service rejected the first event or the token. Check that the token is fresh and the agent id belongs to the account that minted it.
- **The call ends after two minutes of silence.** That is the agent's own setting, not a transport timeout. `scripts/setup-agent.ts` sets `turn.inactivity_check_in_secs: 10`, so the agent checks in after 10 seconds of no speech, and `inactivity_end_call_secs: 120`, so it ends the call after 120. Raise them and run `npm run setup:agent -- --force`.
- **The microphone is blocked.** The page needs HTTPS or `localhost`.

## Limits

The managed path was run against the live API: agent creation, the token route, and a session with a spoken question, a reply and an interruption. The browser microphone path was not tested on a real device. The own-LLM snippets typecheck against `@cartesia/cartesia-js` 4.2.0 but were not run against the live API, so test them before you rely on them.

Cartesia records the audio and transcript of every agent call by default ([observability](https://docs.cartesia.ai/line/infrastructure/observability#call-recordings)). Tell your users, and delete calls you don't need with `DELETE /agents/calls/{call_id}`.
